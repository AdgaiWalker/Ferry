# 双 Git 开发范式

## 今天怎么来的

这个范式来自一次真实的 Skill 工程实践。

原来的理解是：一个项目只需要一个 Git 仓库，代码、PRD、架构、计划、todo、复盘和开发规则
都放在同一个仓库里。实践中发现，AI 参与开发后，这些材料并不属于同一种东西。

```text
代码 = 现实层，是产品真正运行的物质结果。
Skill / PRD / 架构 / 计划 / 规则 = 意识层，是指导现实如何变化的方法系统。
```

代码可以频繁试错，规则需要稳定沉淀。代码出错影响产品运行，规则出错会影响后续所有判断。
因此，同一个项目需要两个版本边界。

## 它是什么

双 Git 开发范式是：

```text
产品代码用一个 Git 管理。
开发 Skill 和文字系统用另一个 Git 管理。
二者服务同一个项目，但拥有不同的版本边界。
```

在 FerrySpec 中，它对应：

```text
产品仓库 = reality，保存真实代码、测试、运行产物和部署配置。
Skill 仓库 = blueprint + .ferry，保存判断规则、PRD、架构、计划、todo、复盘和工具。
archive = 保存历史、阻滞、复盘和进化日志。
```

这不是把项目拆散，而是把项目的现实层和意识层分开上锁。

## 有什么用

双 Git 解决 AI 协作开发中的**安全**边界问题：

- AI 修改代码时，不会轻易污染开发规则。
- AI 整理理论、PRD 或计划时，不会误伤真实代码。
- 代码可以独立回滚，Skill 和规则也可以独立回滚。
- 现实层可以快速试错，意识层可以稳定沉淀。
- 同一项目既能保持连接，又能避免代码和规则互相吞掉。

## 操作边界

```text
进入产品仓库：写代码、改页面、改接口、跑测试、改部署配置。
进入 Skill 仓库：改规则、改 PRD、改架构、改计划、改 todo、改复盘。
进入 archive：归档完成任务、记录阻滞、沉淀 evolution log。
```

AI 可以执行可撤回的现实操作，但以下动作必须经过人类闸门：

- 删除重要文件
- 修改权限和身份系统
- 推送远程仓库
- 对外发布内容
- 公开私密材料
- 修改不可逆数据

## 一句话

```text
代码仓库保护现实实现，Skill 仓库保护思想规则。
双 Git 让 AI 可以大胆执行，也让人保留最终主权。
```
