World Adaptive Protocol for Entropy Reduction

FERRY 不是工具，是人机协作协议

它要处理的不是一次 prompt，而是意图、执行、记忆、进化怎样接成一条链。

Core Judgment

很多问题不是不会做，而是这些东西总是断开的：

  • 人的意图和现实产出
  • 一次对话和下一次复用
  • 人的判断和 AI 的执行

What Ferry Tries To Do

把高熵的混乱、未知和情绪，逐步转成低熵的有序、已知和产出。

Manifesto

FerrySpec 不是一个工具，不是一个平台，不是一个普通框架。

Ferry 更像一个渡者。它渡人的经验、项目的记忆、方法的传承，也渡人机协作中那些本来很容易断掉的东西。

它不是在替人做价值判断，而是在蓝图、现实、记忆之间搭一座桥，让协作不再总是从零开始。

01
对抗断裂：连接主观意图与客观现实。
02
对抗熵增：把混乱情绪与想法转成结构化产出。
03
对抗遗忘：通过日志与复盘，让系统持续进化。

Trinity

Ferry 把长期协作拆成三个可复用部件，不让方法只停在一次对话里。

S
Skill：定规矩，定义宪法、能力、工具库。
F
Flow：干活，在规则指导下执行并过闸门。
L
Log：长记性，记录阻滞，回流成下一次进化。

Where It Fits

它不是只为编程准备，而是把“蓝图 -> 现实”的问题抽象成通用世界协议。

  • 编程开发：PRD / API → SourceCode
  • 创意写作：大纲 / 人设 → 正文章节
  • 法律实务：案件策略 → 证据 / 文书
  • 个人成长：年度 OKR → 每日行动

Dispatch

P0-P4 不是流程装饰，而是状态调度：混沌、规划、执行、修正、进化。

Boundary

AI 给建议，人类拍板担责。不可逆操作必须回到人的主权之下。

它要解决的是协作效能，不是替代人的主权。

一句话： Ferry 想把蓝图、现实、记忆重新接成一条可持续的人机协作链。
